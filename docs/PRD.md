# PDF 편집기 기획서 (PRD)

- 작성일: 2026-11-03
- 상태: 1차 구현 완료

## 1. 목표

PDF·이미지를 브라우저에서 합치고 배치·주석을 더해 다시 PDF로 저장한다.
**비용 0원**(서버 없음, 무료 라이브러리, GitHub Pages 무료 배포)이 전제이며, 이후 **개인 AI와 연결**할 수 있는 구조로 만든다.

## 2. 요구사항과 결정 사항

| # | 요구사항 | 결정 / 구현 |
|---|---|---|
| 1 | HTML 기반, 이미지·PDF 업로드 | 정적 웹앱. 파일 열기, 끌어다 놓기, Ctrl+V 이미지 붙여넣기 |
| 2 | 원본 처리 방식 | 원본 페이지를 **배경**으로 두고 위에 텍스트·이미지·도형을 올림. 원본 글자 직접 수정은 범위 밖 |
| 3 | 드래그로 위치 수정 | 페이지 순서: 왼쪽 썸네일 드래그 / 페이지 안: 캔버스에서 드래그·크기·회전 |
| 4 | 규격 | A4 / 원본 크기 유지 / 이미지 크기에 맞춤 / 영역 직접 지정(mm) |
| 5 | 방향 | 세로·가로 (A4·직접 지정에서 선택, 원본·맞춤은 원본 방향을 따름) |
| 6 | 배치 방식 | 비율 유지 맞춤 / 꽉 채우기 / 늘이기 — A4·직접 지정에서 선택 |
| 7 | 이미지 겹침 | 레이어 순서 4종, 투명도, 회전, 잠금 |
| 8 | 텍스트 | 폰트·크기·굵게·색·정렬·줄 간격, 상자 너비에 맞춰 자동 줄바꿈 |
| 9 | 도형 | 네모·동그라미, 채우기·테두리 색(없음 가능), 테두리 두께 (PPT와 유사한 조작) |
| 10 | 폰트 | 기본: Pretendard, 맑은 고딕. 필요 시 TTF·OTF 추가 (브라우저 저장 / 저장소 배포 두 방식) |
| 11 | 품질 | 원본 PDF는 벡터 그대로 삽입, 이미지는 원본 바이트 그대로 삽입 |
| 12 | 편집 기능 | 실행 취소·다시 실행, 페이지 삭제·복제·회전·빈 페이지, 확대·축소, 요소 복사·삭제 |
| 13 | 배포 | GitHub Pages |
| 14 | 확장성 | 모든 편집을 `commands.js` 한 곳에서 처리하고 `window.PDFEditor` API로 공개. 확장 등록 위치(`js/extensions`)와 패널 자리(`#extensionSlot`) 마련 |

### 규격 용어 정의

- **원본 크기 유지**: 원본 PDF 페이지 크기 그대로. 이미지는 96dpi 기준 (1px = 0.75pt)
- **이미지 크기에 맞춤**: 배경(원본 페이지·이미지)이 **지금 차지하는 영역**에 페이지를 맞춤. 배경을 옮기거나 줄인 뒤 선택하면 그 영역대로 잘림
- **배치 방식**: A4·직접 지정처럼 용지 크기가 원본과 다를 때 배경을 맞추는 방법

## 3. 사용자 흐름

1. 파일 열기(또는 끌어다 놓기) → PDF는 페이지별로, 이미지는 한 장씩 페이지가 됨
2. 왼쪽 썸네일을 드래그해 순서 정리, 필요 시 복제·회전·삭제·빈 페이지 추가
3. 페이지별 규격·방향·배치 설정 (또는 **모든 페이지에 적용**)
4. 텍스트·도형·이미지를 올리고 오른쪽 패널에서 속성 조정
5. **PDF 저장** → `원본파일명_편집.pdf` 다운로드

## 4. 기술 구성 (모두 무료)

| 역할 | 라이브러리 |
|---|---|
| PDF 화면 표시 | pdf.js 3.11.174 |
| 편집 캔버스 | Fabric.js 5.3.0 |
| 페이지 드래그 | SortableJS 1.15.2 |
| PDF 저장 | pdf-lib 1.17.1 + @pdf-lib/fontkit 1.1.1 |
| 폰트 축소(쓴 글자만) | HarfBuzz hb-subset (harfbuzzjs 0.4.2) |

외부 CDN에 의존하지 않도록 모두 `vendor/`에 버전을 고정해 넣었다.

## 5. 구현 중 확인한 이슈와 대응

| 이슈 | 대응 |
|---|---|
| pdf-lib의 폰트 축소(subset) 기능이 한글 글자를 빠뜨림 | HarfBuzz로 직접 축소한 폰트를 넣음 (맑은 고딕 기준 7.3MB → 11KB) |
| Pretendard의 문맥 대체 글자(예: `+`)의 폭이 PDF에 기록되지 않아 간격이 벌어짐 | 실제로 쓴 글자 모양의 폭까지 기록하도록 보정 (`exporter.js`의 `trackGlyphWidths`) |
| 맑은 고딕은 재배포 불가 | 저장 시 PC의 폰트를 불러옴 (Local Font Access API → 실패 시 파일 선택), 브라우저에 보관 |
| 원본 PDF에 회전값(/Rotate)이 있는 페이지 | 저장 시 회전 전 모양으로 넣고 함께 돌려 화면과 동일하게 맞춤 |
| 사진 JPG의 EXIF 회전 정보 | 회전 정보가 있으면 PNG로 변환해 화면과 저장 결과를 맞춤 |

## 6. 검증

Chrome으로 실제 화면을 조작하는 자동 테스트를 돌려 다음을 확인했다.

- 마우스 드래그 이동, Ctrl+Z/Y, Ctrl+C/V/D, Delete, 레이어 순서, 투명도, 한글 입력, 폰트 변경
- 규격 4종 × 방향 × 배치 방식 3종, 빈 페이지·복제·회전·삭제·순서 변경, 확대·축소
- 폰트 추가·유지·삭제, 맑은 고딕 굵게 저장
- 편집 화면과 저장된 PDF를 페이지별로 비교해 위치·회전·투명도·겹침 순서·글자가 일치함
